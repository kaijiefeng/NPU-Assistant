# 管理助手跟随轮次、工具契约与全功能验收

日期：2026-11-20。范围：管理助手多轮稳定性、45 个内建工具、SSE/持久化与真实模型端到端。

## 1. 用户反馈与根因证据

### 1.1 “仅第一轮可用，后续提示模型暂时不可用”

正式库记录显示同一会话首轮正常，第二轮起助手消息为“模型暂时不可用…”。运行日志对应：

```text
模型调用失败（deepseek / deepseek-flash）：模型服务返回了空回复
```

真实 Provider 复现（`deepseek-flash`，OpenAI 兼容）表明：部分请求返回 HTTP 200、`finish_reason=stop`，但 `message.content` 是 286 个空白字符；同一输入在其他请求中可正常返回。空正文是**上游偶发内容异常**，不是用户输入或工具协议问题。

旧实现有三处放大：

1. “空回复”不在可重试集合，单次抖动直接失败；
2. 空回复计入连续失败并触发熔断，三次后 60 秒内所有对话直接返回失败；
3. 失败提示被写入历史并回灌模型，后续轮次更容易复读失败。

### 1.2 “模型工具调用格式不完整，尚未执行该操作”

旧逻辑对残缺 DSML、工具与回复混杂、参数键名差异（`arguments`/`parameters`）一次性终止，没有给模型纠错机会。另发现：

- 模型会输出 `{"tool":"x","arguments":{...}}`，旧解析只认 `args`，参数被静默丢弃；
- 工具目录只有中文参数说明，没有机器可校验的必填清单；
- `read_file` 只能整文件返回且超过 800 行只给尾部，没有分段参数；
- 缺少按关键词定位源码的只读工具，排障时模型反复整文件读取；
- 工具结果统一截断 2400 字符，代码/日志内容被截断后模型只能继续翻页。

真实模型验收还发现两类体验问题：同参重复调用会直接终止（应先用已有结果纠偏）；模型偶发把 `ds_safety` 内部安全分类文本混入正文，旧逻辑会原样展示。

## 2. 修复

### 2.1 模型调用与上下文

- 空正文加入可重试集合；仍为空时自动降级为**不带 JSON 输出约束**的普通模式再请求一次。
- 空正文只记 warning，不计入熔断，避免一次抖动锁死后续会话。
- 失败提示、DSML 占位文本、内部安全标记不再回灌历史。
- 单次输出预留从 1400 提升到 4096 tokens；压缩时若目标预算过紧，优先保留最新一条工具结果，但单条超大消息仍会被摘要，避免挤爆窗口。

### 2.2 协议与工具契约

- JSON 工具对象兼容 `tool`/`name`/`function` 与 `args`/`arguments`/`parameters`，字符串参数自动解析。
- 残缺协议、工具与回复混杂、参数非对象：先自动纠偏两次，仍失败才返回未完成说明。
- 工具目录新增 `required`；服务端按 `parameters` 校验必填项和未知参数，错误返回给模型自纠。
- 同参重复调用：第一次不执行，提示模型使用已有结果或换工具；第二次才停止。
- `read_file` 新增 `start`/`lines`，默认前 100 行、最多 200 行；`read_file`/`read_logs` 单轮最多 8/6 次。
- 新增只读 `search_repo`：纯文本关键词搜索仓库源码/配置，返回文件、行号与片段；路径限定仓库、扩展名白名单、跳过依赖与数据目录。
- `read_file`/`search_repo`/`read_logs` 工具结果预算分别放宽到 16000/10000/10000 字符，普通工具仍为 2400。
- `gap_link` 要求至少一个 `document_id`/`page_id`；任务、反馈、告警参数补充枚举说明。
- 模型正文包含 `ds_safety` 或 `[用户未成年]` 时判定为格式异常，纠偏或明确说明，不展示原文；前端历史回放同样拦截。

## 4. 真实模型端到端

隔离实例：临时数据目录 + 真实 Provider 配置副本，端口 8123；不读写正式库，不扫描真实资料。

### 4.1 多轮跟随（最终构建）

同一会话连续 4 轮：知识缺口 → 追问如何补缺口 → 扫描功能步骤 → 默认扫描目录。

- 4/4 `stop_reason=completed`，`delta` 与 `done.reply` 完全一致；
- 后续轮次全部正常，无“模型暂时不可用”；
- 默认目录问句命中确定性查询，仅调用一次 `get_scan_directory`；
- 持久化 8 条消息（4 用户 + 4 助手）。

### 4.2 全功能（14 轮）

同一会话连续 14 轮，覆盖：系统总览、源文件列表/详情、缺口列表/详情、订阅详情、任务/告警、运维任务、运行日志、源码分段、代码搜索、缺口解决、告警确认、危险删除确认、扫描目录保存、文本收录。

- 14/14 轮均返回最终正文；除危险删除按设计停在 `confirmation_required` 外，其余 `completed`。
- 危险删除实际调用 `delete_document`，服务端返回“尚未执行”，数据库中文档仍为 `ready`；缺口 `resolved`、告警 `acknowledged` 与回复一致。
- 文本收录真实生成 1 篇源文件与 1 个词条。
- 会话持久化 28 条消息（14 用户 + 14 助手）。
- 运行日志记录到真实空正文抖动，系统自动重试/降级后继续完成，未再出现整轮失败。

### 4.3 代码排障

- “搜索 `_record_failure_or_note`”：一次 `search_repo` + 一次 `read_file`，准确给出定义行与 4 处调用；
- “读取 llm.py 开头确认重试常量”：`read_file`/`search_repo` 共 6 次，返回正确的重试与熔断常量，不再出现 14 次翻页。

## 5. 边界

- 上游模型仍可能对特定措辞返回内部安全分类文本；系统会拦截并给出“无法展示的内部标记”说明，不保证模型对任意问题都生成业务回答。
- 真实模型输出具有随机性；本轮成功复验不保证后续永不出现新的格式差异，错误分支会明确反馈而非虚报成功。
- 危险工具只在隔离实例验证了确认门，没有执行真实删除、全量重建或运维批准。
- 未改动界面布局，本轮未重复截图；前端历史防护通过脚本检查。
- 未提交或推送代码。

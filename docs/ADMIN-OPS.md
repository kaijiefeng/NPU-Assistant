# NPU-Assistant 管理员与运维手册

> 适用版本：v0.2.0（2026-11-09 发布）  
> 读者：辅导员、学院管理员、部署老师、值班运维  
> 目标：**不需要深入开发经验**，按步骤完成日常管理、内容运营、机器人配置、备份与排障。  
> 配套文档：客户使用手册 `frontend/manual/index.html`、产品总览 `frontend/manual/product.html`、开发手册 `docs/DEVELOPER.md`、路线图 `docs/ROADMAP.md`。

## 0. 先分清三种“管理员”

| 角色 | 你主要做什么 | 你需要会什么 |
|------|--------------|--------------|
| **内容管理员（辅导员）** | 收录资料、检查词条、编辑/重建、配置快捷问题、回答学生工单 | 会用浏览器和手机；不需要命令行 |
| **系统管理员（部署老师）** | 启动服务、配模型、配机器人、备份、升级、安全、管理账号 | 会 PowerShell 基本命令；能看日志 |
| **只读观察者** | 查看词条、服务台和工单，不能修改 | 会用浏览器 |
| **开发/技术支持** | 改代码、加功能、处理数据库/接口问题 | 见 `docs/DEVELOPER.md` |

> 本手册覆盖前三类。遇到“改代码/查数据库”的问题，直接交给开发/技术支持。

### 0.1 界面导航地图（v0.2.0）

左侧只有四个一级入口，原有页面已收进「运营」和「设置」：

| 一级入口 | 二级页面 | 用途 |
|----------|----------|------|
| 对话 | — | 学生/老师提问 |
| 知识库 | 浏览 / 内容管理 | 浏览词条；有权限时进入收录、源文件、词条维护 |
| 运营 | 服务台 / 任务与告警 / 审计日志 | 反馈缺口、工单危机、后台任务、操作追溯 |
| 设置 | 助手设置 / 模型 / 机器人 / 成员与权限 / 我的账号 | 人设与安全、模型、机器人通道、账号权限 |

> 旧地址（`#/manage`、`#/insights`、`#/jobs`、`#/models`、`#/bots`、`#/team`）会自动跳到对应新页面，书签无需修改。

## 1. 系统长什么样

- 一个后端进程（FastAPI）同时提供网页、手机页面和 API。
- 数据都在 `backend/data/`：
  - `app.db`：SQLite 数据库（源文件、词条、会话、模型、机器人通道、设置）。
  - `uploads/`：上传/收录的原始文件。
  - `wiki_seed.json`：预编译 Wiki 快照（无 Key 也能离线演示）。
- 前端是纯静态文件，由同一个服务托管。
- 默认地址：`http://127.0.0.1:8000`；手机访问用 `-Lan` 启动。

## 2. 首次部署（Windows，约 10 分钟）

### 2.1 准备

- Windows 10/11。
- Python 3.11+（安装时勾选“Add Python to PATH”）。
- 不需要 Node.js、不需要数据库服务。
- 能访问模型 API（如 DeepSeek）或本机 Ollama（可选）。

### 2.2 一键启动

在项目根目录打开 PowerShell：

```powershell
# 方式 A：一键建环境 + 装依赖 + 启动
.\scripts\bootstrap.ps1
```

或者分步：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
.\scripts\run.ps1
```

启动后浏览器打开 <http://127.0.0.1:8000>。

### 2.3 首次启动会自动做什么

1. 创建 `backend/data/app.db`。
2. 写入默认 mock 模型和控制台机器人通道。
3. 如果 `wiki_pages` 为空，自动导入 `backend/data/wiki_seed.json`（预编译词条）。
4. 生成默认设置（人设、欢迎语、快捷问题、引用开关）。

> 没有配置真实模型时，可以浏览词条、体验降级问答；上传编译和高质量回答需要真实模型。

### 2.4 创建管理员账号（推荐）

打开「设置 → 成员与权限 → 新增成员」，按分工选择角色：

| 角色 | 能做什么 |
|------|----------|
| 超级管理员 | 全部功能 + 成员管理 + 审计 |
| 管理员 | 内容、模型、机器人、设置、服务台、工单 |
| 辅导员 | 服务台、知识缺口、工单回复、危机处置；只读内容 |
| 只读 | 查看知识库、服务台、工单，不能修改 |

首次打开页面如果没有账号，会提示「初始化管理员」：填写用户名、显示名称、密码（至少 8 位）即可。以后新增成员、停用、重置密码都在同一页完成。

> **重要**：至少保留一名启用的超级管理员。系统不允许删除/降级最后一名超级管理员，避免把自己锁在门外。

### 2.5 手机访问

```powershell
# 电脑和手机同一 Wi-Fi
.\scripts\run.ps1 -Lan
```

脚本会：
- 监听 `0.0.0.0`；
- 打印手机可访问的局域网地址；
- **自动生成并打印管理令牌**（仅本次启动有效，除非你写入环境变量）。

然后电脑打开 `http://127.0.0.1:8000` → 右上角「手机扫码」→ 手机扫码。

首次手机打不开，通常是防火墙：

```powershell
# 管理员 PowerShell
New-NetFirewallRule -DisplayName "NPU-Assistant 8000" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow
```

## 3. 管理令牌：最重要的安全开关

### 3.1 它是什么

管理令牌相当于“万能钥匙”。设置后：
- 上传、收录、编辑词条、删除、重建、模型管理、机器人配置、设置修改等写操作都需要令牌。
- 学生问答 `POST /api/chat` 仍公开。
- 历史会话接口需要令牌（因为含学生隐私）。

> v0.2.0 起优先使用「设置 → 成员与权限」里的个人账号（见 §2.4）。令牌继续兼容，主要用于应急和脚本。

### 3.2 三种设置方式

| 方式 | 适合 | 做法 |
|------|------|------|
| 启动脚本自动生成 | 临时演示、局域网 | `.\scripts\run.ps1 -Lan`，看控制台打印 |
| 环境变量 | 长期部署（推荐） | `$env:NPU_ADMIN_TOKEN = "24位以上随机串"` 后启动 |
| 设置页启用 | 本机首次启用 | 「设置 → 助手设置 → 移动访问与安全」输入 ≥16 位随机串 → 保存/启用 |

> 环境变量优先。设置页写入的令牌会保存到 `backend/data/admin_token.txt`，重启仍有效。
> 如果已经用环境变量控制，设置页会提示去部署配置修改。

### 3.3 安全规则

- 公网/局域网多人使用必须设置强随机令牌（≥24 位）。
- 不要把令牌发群、截图、写进公开文档。
- 换人/离职时更换令牌，并同步更换机器人 token。
- 对外监听但未设令牌时，服务会拒绝启动（除非显式 `NPU_ALLOW_INSECURE_LAN=1`，仅可信内网临时演示）。

### 3.4 忘记令牌怎么办

- 如果由环境变量控制：查部署配置/启动脚本。
- 如果由设置页写入：查看 `backend/data/admin_token.txt`（仅本机管理员可读）。
- 都不行：停止服务，删除/重命名 `admin_token.txt`，在本机重新启用；或临时设置新的 `NPU_ADMIN_TOKEN` 启动。

### 3.5 账号与令牌的关系

- **推荐用账号登录**：每个人一个账号，可审计、可停用、可分工；会话默认 7 天，过期后需重新登录。
- **令牌是应急/脚本入口**：`X-Admin-Token` 仍然有效，等同于超级管理员；适合临时排障和自动化脚本。不要长期多人共用。
- 两者可以并存：已有账号时，登录页仍提供「使用管理令牌进入」。
- 改密码后其他设备不会被立刻踢下线；如怀疑泄露，让超级管理员「重置密码」或「停用账号」，会注销该账号全部会话。
- 所有管理写操作都会进「运营 → 审计日志」，可按账号、操作、时间筛选。登录失败也会记录（不记录密码）。

### 3.6 首次无人值守创建账号

适合脚本化部署：首次启动前设置环境变量，服务会自动创建超级管理员（仅当账号表为空时）：

```powershell
$env:NPU_ADMIN_USERNAME = "admin"
$env:NPU_ADMIN_PASSWORD = "请换成至少8位的强密码"
.\scripts\run.ps1
```

HTTPS 部署时再加 `$env:NPU_COOKIE_SECURE = "1"`，让登录 Cookie 只走加密连接。

## 4. 模型配置（决定能不能编译、回答质量）

### 4.1 推荐：DeepSeek（OpenAI 兼容）

1. 打开「模型」页 →「Provider」标签 → 新建 Provider。
2. 类型选 `openai`。
3. Base URL：`https://api.deepseek.com/v1`。
4. API Key：填 DeepSeek 的 Key（只保存在服务器，页面脱敏）。
5. 保存后点「测试连接」。
6. 在「模型」标签新建模型：模型名 `deepseek-chat`，显示名如「DeepSeek Chat」。
7. 点「设为默认」。

### 4.2 本地：Ollama

1. 本机安装 Ollama 并拉取模型（如 `ollama pull qwen2.5:7b`）。
2. Provider 类型选 `ollama`。
3. Base URL：`http://127.0.0.1:11434`。
4. 模型名填 Ollama 的模型名。
5. 测试连接 → 设为默认。

> 本地模型质量/速度取决于机器配置；7B 级别可用于演示，生产建议更大模型或 API。

### 4.3 内置 mock

- 仅用于链路演示；**不能编译词条**，回答会降级为词条摘录。
- 没有 Key 时保留它作为兜底，不要删除。

### 4.4 常见模型问题

| 现象 | 可能原因 | 处理 |
|------|----------|------|
| 测试连接失败 | Key 错、余额不足、网络不通、Base URL 多了/少了 `/v1` | 逐项检查；用 curl 测同一地址 |
| 上传后 `status=failed` | 模型未配置、Key 失效、超时 | 看源文件卡片错误；修模型后点「重新编译」 |
| 回答 `fallback=true` | 模型不可用或调用失败 | 检查模型；降级回答仍带词条引用 |
| 编译很慢/超时 | 文件大、单元多、模型慢 | 拆分文件；换更快模型；避开高峰 |
| 回答质量差 | 模型太小、词条太碎/太长 | 换模型；人工编辑词条；重新编译 |

## 5. 知识库日常运营（核心工作）

### 5.1 三种收录方式怎么选

| 方式 | 适合 | 操作 | 注意 |
|------|------|------|------|
| **链接** | 学校官网、部门网页、公众号文章 | 知识库 → 内容管理 → 收录资料 → 粘贴链接（一行一个，最多 5 条） | 微信反爬时改用文本 |
| **文本** | 微信群通知、复制来的正文、无网页资料 | 填标题（可留空）+ 正文（≥30 字） | 最稳，推荐公众号文章用这个 |
| **文件** | Word/PDF/Excel/Markdown/TXT/HTML | 上传（≤20MB，可多选） | 上传后进后台队列编译，不阻塞页面；失败可重试 |

支持格式：`.md .markdown .txt .pdf .docx .doc .xlsx .csv .json .html .htm`。  
暂不支持 PPT/PPTX；可另存为 PDF 或复制正文。

### 5.2 收录后检查清单

1. 打开「知识库 → 内容管理 → 源文件」，确认状态为「已就绪」。
2. 点「眼睛」查看生成的词条。
3. 检查：
   - 标题是否像一个可检索的主题（如「国家奖学金申请」）；
   - 正文是否保留了原文的金额、时间、电话、地点；
   - 来源锚点的「章节 + 原文摘录」是否能对上；
   - 标签是否合理（影响目录分组和导航）。
4. 有问题：
   - 小问题：直接编辑词条（标题/摘要/正文/别名/标签），保存后 `version+1`。
   - 大问题：回到源文件点「重新编译」；仍不行就改用文本方式或拆分文件。

### 5.3 什么时候用「全部重建」

- 更换了模型，想让所有词条按新模型重写。
- 编译提示词/规则有较大调整。
- 大量源文件更新。

注意：
- 重建是后台任务，耗时与文件数量/大小相关。
- 不要重复点击；等待轮询完成。
- 重建前先备份（`.\scripts\backup.ps1`）。
- 重建不会删除源文件，但可能合并/更新词条，人工编辑可能被覆盖，重要词条先导出/记录。

### 5.4 查看编译进度

上传文件后在「运营 → 任务与告警 → 任务」查看进度：

- **排队中 / 执行中**：可看到百分比和当前步骤；
- **失败**：卡片上显示原因，点「重试」（最多 2 次）；模型 Key/网络问题先修模型；
- **已完成**：点「查看文档」跳到源文件，检查生成的词条；
- **取消**：排队任务立即取消；执行中的任务会在当前步骤后停止，已生成的内容保留。

> 关闭页面不会中断任务；但**重启服务**会中断正在执行的任务，重启后需手动重试。

### 5.5 删除的后果

- 删除源文件会删除**仅由它生成的词条**；共享词条只移除该来源。
- 删除词条会影响引用它的回答。
- 删除是硬删除，没有回收站；删除前先备份。
- 文档列表支持下载原始文件，可用于留档。

### 5.6 词条质量建议

- 一个词条只讲一个主题；不要把所有奖助政策塞进一个词条。
- 标题用学生常说的词；别名补“国奖/国励/综测”等口语。
- 标签控制在 1-3 个，避免目录分裂。
- 金额、截止日期、电话必须保留原文写法；不要手写推测。
- 对年年变化的政策，在正文里写清“适用学年/以当年通知为准”。

## 6. 学生侧设置

「设置 → 助手设置 → 基础」可以改：

| 设置 | 作用 | 建议 |
|------|------|------|
| 辅导员名称 | 人设名称（默认“小南”） | 用学生熟悉的称呼 |

| 引用开关 | 是否展示引用 | 建议保持开启 |
| 词条数量/上下文字数 | 每次送入模型的词条数与长度 | 默认 3 / 9000；过大增加成本 |
| 机器人尾注 | QQ/微信回答末尾提示 | 保留“以官方通知为准” |

## 7. 机器人配置

### 7.1 三类通道

| 通道 | 适合 | 需要公网吗 | 关键配置 |
|------|------|------------|----------|
| **控制台调试** | 本地演示、培训 | 不需要 | 无；直接在「调试」里模拟 |
| **QQ 官方机器人** | 无公网 IP 的校园内网 | **不需要 Webhook** | AppID、AppSecret、sandbox、管理员 openid |
| **微信公众号** | 学校公众号 | 需要公网 HTTPS | Token、AppID、管理员 openid |

### 7.2 QQ 官方机器人（推荐无公网场景）

1. 在 QQ 开放平台创建机器人，拿到 AppID / AppSecret。
2. 「机器人 → 通道 → 快速添加 → QQ 官方机器人」。
3. 填 AppID / AppSecret；沙箱环境选 sandbox。
4. 保存后服务会主动连接 WebSocket；通道状态变在线即成功。
5. 管理员私聊机器人发 `#帮助`，拿到自己的 openid，填入 `admin_user_ids`。
6. 群聊需 @ 机器人；默认只处理 @ 消息。

> 不需要在 QQ 后台填 Webhook，也不需要公网 IP。回答超长会自动裁剪，避免平台 1800 字限制。

### 7.3 微信公众号

1. 公众号后台 → 开发 → 基本配置，拿到 Token / AppID。
2. 「机器人 → 通道 → 快速添加 → 微信公众号」。
3. 填 Token（必须与后台一致，不能留空/默认值）。
4. 把通道显示的 URL 填到公众号后台「服务器配置」。
5. 管理员给公众号发 `#帮助`，把 openid 填入 `admin_user_ids`。
6. 公众号仅支持明文模式；5 秒内先回“已开始收录”，结果到「知识库 → 内容管理」查看。

### 7.4 管理员命令

| 发送内容 | 效果 |
|----------|------|
| 直接发链接 | 自动识别并收录 |
| `#入库 <链接>` / `#收录 <链接>` | 显式收录 |
| `#状态` | 词条数、源文件数、默认模型 |
| `#帮助` | 命令列表 + 你的用户 ID/openid |

> 只有 `admin_user_ids` 里的用户能触发入库；普通用户发链接会被当作问题回答。
> 管理员身份靠平台 token/签名校验，不靠昵称。

### 7.5 机器人排障

| 现象 | 检查 |
|------|------|
| 通道离线 | 配置是否保存；QQ 官方 AppSecret 是否正确；服务能否出网访问腾讯网关 |
| 发消息没回复 | 群聊是否 @；`group_mention_only`；Webhook 是否填对；后端日志 |
| 回复“仅限管理员” | 发送者 ID 不在 `admin_user_ids`；用 `#帮助` 查看 ID |
| 微信回调失败 | Token 是否一致；服务器时间是否准确（±300 秒）；URL 是否公网可达 |
| 回答被截断 | QQ 官方 1800 字限制；正文已自动裁剪；长答案建议引导看文件链接 |
| 文件链接打不开 | 手机是否能访问服务地址；配 `NPU_PUBLIC_URL` 或开公网隧道 |

## 8. 手机扫码与公网访问

### 8.1 局域网（推荐先跑通）

```powershell
.\scripts\run.ps1 -Lan
```

- 电脑和手机同一 Wi-Fi。
- 电脑打开页面 →「设置 → 助手设置 → 移动访问与安全 → 扫码 / 公网访问」。
- 手机扫码；需要管理操作时填同一令牌。

### 8.2 公网 HTTPS（4G/5G、公众号回调、PWA）

- 安装 cloudflared：

```powershell
winget install Cloudflare.cloudflared
```

- 设置强令牌后启动 `-Lan`。
- 扫码弹窗点「一键开启公网访问」；二维码切换为 `https://xxx.trycloudflare.com`。
- 临时隧道地址公网可访问，用完关闭；长期使用建议固定域名/Nginx 反代。

### 8.3 固定公网地址

```powershell
$env:NPU_PUBLIC_URL = "https://npu.example.edu.cn"
.\scripts\run.ps1 -Lan
```

> 机器人回答里的文件链接会用这个地址；不配的话手机可能打不开。

## 9. 备份、恢复与升级

### 9.1 备份

```powershell
.\scripts\backup.ps1
```

生成 `backups/npu-assistant-YYYYMMDD-HHmmss.zip`，包含：
- `app.db`（SQLite 一致性快照）
- `uploads/`（原始文件）
- `wiki_seed.json`
- `seed_docs/`

建议：
- 每周一次；大更新/重建前一次。
- 复制到另一台设备/网盘，不要只留本机。
- 备份文件含学生问答与资料，注意保密。

### 9.2 恢复

1. 停止服务（Ctrl+C）。
2. 解压备份。
3. 覆盖 `backend/data/app.db`、`uploads/`、`wiki_seed.json`、`seed_docs/`。
4. 重启服务。
5. 打开知识库确认词条/源文件数量；抽查一次问答。

> 不要在服务运行时直接复制 `app.db`（有 WAL 文件）；用 `backup.ps1` 做一致性快照。

### 9.3 升级

1. 先备份。
2. 拉取新代码 / 解压新版本。
3. 安装依赖：`.\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt`。
4. 重启服务；启动时会自动做数据库增量迁移。
5. 打开 `/api/health` 和首页，确认版本、词条数正常。
6. 抽查一次问答和一次上传。

> 升级不会删除 `backend/data`；但不要跨大版本跳级，按 CHANGELOG 顺序升级。

## 11. 排障手册

### 11.1 服务起不来

| 检查 | 处理 |
|------|------|
| Python/venv 是否存在 | `.\scripts\bootstrap.ps1` |
| 端口被占用 | `.\scripts\run.ps1 -Port 8010` |
| 对外监听但没令牌 | 设置 `NPU_ADMIN_TOKEN`；或仅本机用 `127.0.0.1` |
| 依赖缺失 | 重装 `requirements.txt` |
| 数据库损坏 | 从备份恢复；不要手工改 DB |

### 11.2 页面能开但接口报错

- 打开 <http://127.0.0.1:8000/api/health> 看是否 `status: ok`。
- 401：令牌没填/填错/服务端令牌变了。
- 403：对外监听未设令牌，或权限不足。
- 429：提问太频繁（默认 30 次/分/IP），稍后再试。
- 500：看后端控制台日志；记录时间、操作、错误。

### 11.3 收录失败

| 提示 | 处理 |
|------|------|
| 不支持的文件类型 | 转 PDF/TXT；PPT 暂不支持 |
| 文件过大 | 压缩/拆分；或调大 `NPU_MAX_UPLOAD_MB` |
| 网页超过 8MB | 改用文本粘贴；或调大 `NPU_URL_IMPORT_MAX_BYTES` |
| 微信验证/反爬 | 复制正文用文本收录 |
| 重复 | 同一 URL 已收录；直接看已有词条 |
| 模型未配置 | 配模型后重新编译 |
| 解析失败 | 换格式/OCR；扫描 PDF 需要 OCR 工具 |

### 11.4 学生说“答得不对”

1. 让 TA 点开引用，核对原文。
2. 看词条是否过期/来源是否错误。
3. 修正源文件或词条 → 重新编译。
4. 如果 Wiki 没有，补资料；如果问题超出范围，建议联系辅导员。
5. 记录问题到内容待办（v0.2.0 会有缺口工作台）。

### 11.5 机器人不回复

- 通道状态是否 online。
- 群聊是否 @；私聊是否被平台限制。
- Webhook/WS 是否连通；token 是否一致。
- 看「机器人 → 日志」和后端控制台。
- 微信公众号 5 秒限制：先回“已开始收录”是正常的。

- [ ] 公网/局域网必须设置强随机 `NPU_ADMIN_TOKEN`（≥24 位）。

- [ ] 上传真实文件、调用第三方模型前完成学校数据合规评估。

## 13. 应急处理

### 13.1 令牌泄露

1. 立即更换 `NPU_ADMIN_TOKEN`（环境变量或设置页轮换）。
2. 重启服务。
3. 到「运营 → 审计日志」按账号、操作与时间检查异常上传/删除/设置修改；必要时结合服务日志与备份对比。
4. 更换机器人 token。

### 13.2 模型不可用

1. 切到备用 Provider/模型（模型页设为默认）。
2. 没有备用时，系统会降级为词条摘录（`fallback=true`），仍可回答但质量下降。
3. 在模型页测试连接，检查余额/网络。
4. 修复后重新测试；必要时重新编译受影响的词条。

### 13.3 数据损坏/误删

1. 停止服务。
2. 从最近备份恢复 `app.db` + `uploads`。
3. 重启，检查词条/源文件/会话。
4. 如果没有备份：不要继续写入，联系技术支持尝试从 WAL/文件恢复。

### 13.4 公网隧道异常

1. 关闭再开启「一键开启公网访问」。
2. 检查 cloudflared 是否安装/在 PATH。
3. 临时改用局域网访问。
4. 长期方案：固定域名 + Nginx/Caddy + HTTPS。

## 16. 运行时环境变量（完整表）

> 首页 README 只保留最常用项；完整清单以本节为准（与 `backend/app/config.py` 一致）。

| 变量 | 默认 | 说明 |
|------|------|------|
| `NPU_HOST` / `NPU_PORT` | `127.0.0.1` / `8000` | 监听地址与端口 |
| `NPU_DATA_DIR` | `backend/data` | 数据目录（数据库、上传文件） |
| `NPU_DB_PATH` | `backend/data/app.db` | SQLite 数据库路径 |
| `NPU_WIKI_SEED_PATH` | `backend/data/wiki_seed.json` | 预编译 Wiki 快照路径 |
| `NPU_MAX_UPLOAD_MB` | `20` | 单文件上传上限 |
| `NPU_AUTO_SEED` | `1` | 首启是否自动导入 Wiki 快照 |
| `NPU_ADMIN_TOKEN` | 空 | 设置后管理类写操作与历史会话接口需 `X-Admin-Token` 请求头（学生问答 `POST /api/chat`、GET、机器人 webhook 不受影响）；也可在设置页首次启用/替换（环境变量优先，环境变量存在时 UI 轮换返回 409） |
| `NPU_CORS_ORIGINS` | 空 | CORS 白名单（逗号分隔）；默认关闭，同源 SPA 不需要 |
| `NPU_ALLOW_INSECURE_LAN` | `0` | 对外监听且未设管理令牌时，服务默认拒绝启动；仅可信内网临时演示可设 `1` |
| `NPU_BOT_ALLOW_INSECURE` | `0` | 机器人 webhook 空 token 逃生开关，仅限本机调试 |
| `NPU_QQ_OFFICIAL_AUTOSTART` | `1` | 启动时是否自动连接已启用 `qq_official` 通道的 QQ 网关；测试环境设 `0` |
| `NPU_URL_IMPORT_ALLOW_PRIVATE` | `0` | URL 收录是否允许私网/回环地址（内网资料才临时开启） |
| `NPU_URL_IMPORT_MAX_BYTES` | `8388608` | URL 抓取响应大小上限（默认 8MB，可调） |
| `NPU_URL_IMPORT_MAX_URLS` | `5` | 批量收录单次链接上限 |
| `NPU_SCAN_ROOTS` | 空 | 「知识库 → 内容管理 → 扫描文件夹」允许扫描的根目录（多个用路径分隔符）；为空时允许任意存在的文件夹（仅管理员可用），生产环境建议显式限定 |
| `NPU_SCAN_MAX_FILES` | `200` | 单次文件夹扫描最多收录的文件数 |
| `NPU_SCAN_MAX_DEPTH` | `4` | 文件夹扫描的目录深度上限 |

### 16.1 重新生成预编译 Wiki 快照（会消耗 LLM Token）

```powershell
$env:NPU_SEED_API_KEY="sk-..."
$env:NPU_SEED_BASE_URL="https://api.deepseek.com/v1"   # 可选
$env:NPU_SEED_MODEL="deepseek-chat"                    # 可选
.\.venv\Scripts\python.exe scripts\build_wiki_seed.py
```

脚本使用临时数据目录编译，不会污染 `backend/data/app.db`；产物写入 `backend/data/wiki_seed.json`。冷启动且 `wiki_pages` 为空时自动导入，也可在「知识库 → 源文件」点「导入预编译快照」。

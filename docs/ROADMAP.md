## 1. 怎么读这份路线图

### 1.1 状态图例

| 状态 | 含义 |
|------|------|
| ✅ 已交付 | 已合并、测试通过、可演示 |
| 🚧 进行中 | 当前迭代在做 |
| 📋 计划 | 已排期，未开始 |
| 💡 待评估 | 有价值，但依赖/成本/合规未定 |
| ⛔ 非目标 | 明确不做（至少当前阶段） |

### 1.2 优先级

- **P0**：服务闭环/安全/可用性，必须做。
- **P1**：内容治理与运营效率，显著提升长期价值。
- **P2**：体验与合规完善。
- **P3**：规模化/系统集成，依赖外部条件。

### 1.3 估算假设

- 2 名工程师（1 后端 + 1 前端）+ 0.5 QA。
- 单位为 **人日（PD）**，不含评审、等待外部接口、学校审批。
- 实际排期以迭代评审为准；本文档只做方向与优先级承诺，不做日期硬承诺。

## 2. 当前基线：v0.1.7（已交付）

**主题**：源文件可下载 + 回答自动附带相关文件链接（Web/QQ/微信）。

| 能力 | 状态 | 说明 |
|------|------|------|
| 学生 Web 问答 | ✅ | 多轮、引用、历史会话（需令牌）、快捷问题 |
| LLM Wiki 知识库 | ✅ | 10 种格式、编译词条、来源锚点、编辑/重建/删除 |
| 双层引用 | ✅ | 词条 + 源文件·章节·原文摘录 |
| 快速收录 | ✅ | URL/文本/批量/手机；转发即入库 |
| 模型管理 | ✅ | OpenAI 兼容（DeepSeek）、Ollama、mock |
| 机器人 | ✅ | QQ 官方、微信公众号、控制台（OneBot 11 已移除） |
| 手机/公网 | ✅ | 扫码、局域网、Cloudflare 隧道、PWA |
| 远程兜底 | ✅ | Wiki 无命中/不完整时查官网/公众号，不写库 |
| 完整性判断 | ✅ | 规则 + LLM 裁判 |
| 源文件下载/文件链接 | ✅ | 引用卡下载/原文；机器人附链接 |
| 评测基线 | ✅ | v2026.21：479 可答 + 10 不可答；检索/引用/拒答 100% |

**已知限制**：单进程 SQLite、上传同步编译、无流式、单一管理令牌、无反馈/转人工/时效性/账号角色。

## 7. 明确不做 / 待评估

### 7.1 明确不做（当前阶段）

| 项 | 原因 |
|----|------|
| embedding / 向量库 / rerank | 与 LLM Wiki 设计冲突；导航靠词条+别名+关键词 |
| 开放域闲聊 | 政策场景风险；只做校园范围 + 寒暄 |
| 自动心理诊断 | 伦理/法律风险；只做求助引导与人工升级 |
| 多级复杂工单/排班 | v0.2.0 先做最小可用；复杂流程等真实需求 |
| 全渠道富媒体主动推送 | 平台限制/成本；先做 Webhook + 站内通知 |

### 7.2 待评估（需要产品/学校决策）

1. 危机通知是否要短信/电话？值班表谁维护？
2. 转人工 SLA 是否只算工作时间？寒暑假/夜间如何？
3. 学生是否必须登录？还是匿名 + 工单 token？
4. 账号是否对接学校 SSO？本地账号能否接受？
5. 内容分级标准由谁定？内部文件范围？
6. 数据保留期限（聊天/危机/审计）？
7. 是否允许辅导员在 Web 端直接回复学生？身份如何展示？
8. 多学院是“一套多租户”还是“每院独立部署”？

## 9. 路线图维护规则

1. **每月**复盘一次：状态、优先级、估算是否需要调整。
2. 新需求先进入“待评估”，明确用户问题/验收/依赖后再排期。
3. 已排期需求变更，先改 PRD/本文件，再动代码。
4. 交付后把状态改为 ✅，并在 `CHANGELOG.md` 记录。
5. 不做“只加需求不删需求”：低价值/长期不做的项移到“明确不做/待评估”。

# 回答完整性判断与联网兜底（v0.1.5）

## 目标

Wiki 命中但回答不完整时，也能转学院官网/官方公众号补充检索；完全搜不到再返回无信息。

## 决策流程

```text
Wiki 选页
  ├─ 无词条 → 联网兜底 → 有结果则返回；否则无信息
  └─ 有词条 → 生成回答
       ↓
     规则完整性判断
       ├─ 明确完整 → 直接返回
       ├─ 明确不完整 → 联网补充
       └─ 不确定且存在具体槽位 → LLM 裁判
                                  ├─ complete=true → 返回
                                  └─ complete=false → 联网补充
```

## 规则判断

按问题中的具体槽位检查回答与引用：

- 时间/日期；
- 电话/邮箱/地点；
- 计算公式/权重/分值；
- 名单/人员；
- 条件/资格；
- 金额/人数等数值。

同时检查：

- 是否有引用；
- 问题关键词覆盖率；
- 是否出现“由学院制定”“具体以……为准”等泛化表述。

## LLM 裁判

只在规则置信度不足、且问题存在具体槽位时调用，要求只输出 JSON：

```json
{
  "complete": false,
  "confidence": 0.88,
  "missing": ["具体分值"],
  "need_remote": true,
  "reason": "回答只说明模块，没有计算规则"
}
```

约束：

- 只判断完整性，不回答用户问题；
- 不允许引入新政策；
- 失败/超时/非 JSON → 回退规则判断；
- mock 模型不调用；
- 结果缓存 10 分钟。

## 联网补充策略

- Wiki 无引用：远程结果替换无信息回复；
- Wiki 有引用但不完整：保留 Wiki 回答，追加“补充检索”段落；
- 远程结果必须通过主题相关性过滤；
- 最多 3 条；
- 不写入知识库；
- 完全无结果：保留原回答/无信息，不硬塞无关引用。

## 配置

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `NPU_REMOTE_FALLBACK` | `1` | 是否启用官网/公众号兜底 |
| `NPU_LLM_JUDGE` | `1` | 是否启用 LLM 完整性裁判 |

## 返回字段

```json
{
  "retrieval": {
    "wiki_used": true,
    "remote_used": true,
    "complete": false,
    "reason": "llm:缺少具体分值"
  }
}
```


- 远程无结果 → 保持无信息。

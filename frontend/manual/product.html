01为什么现在需要它

学生的问题高度重复，政策文件却分散在官网、公众号、群文件和老师电脑里；新辅导员上手慢，回答口径还不一致。

🔁

重复问答消耗辅导员

奖助、请假、档案、宿舍等问题每届都问；同样的话一天要回很多遍。

🗂️

政策散落、版本不清

通知在官网、公众号、群文件里；学生不知道哪份最新，老师也难统一口径。

🕵️

普通机器人不可核对

通用大模型会编造金额、截止日期和电话；学生不敢信，老师不敢用。

目标不是“再做一个聊天机器人”，而是把辅导员掌握的文件变成可查询、可核对、可维护的知识资产。

03核心能力

从“资料进来”到“学生问到”，一条完整链路；日常维护主要在手机上完成。

📚

LLM Wiki 知识库

上传 md/txt/pdf/docx/doc/xlsx/csv/json/html，自动解析、按章节编译成词条，并校验来源摘录。

🔗

双层引用

每张引用卡同时给出词条与“源文件 · 章节 · 原文摘录”；支持下载原文件/打开原文。

📱

手机转发即入库

辅导员把官网/公众号链接转发给机器人，或粘贴文本，自动抓取、编译并回复结果。

💬

全渠道复用

Web/PWA、QQ 官方机器人、微信公众号、控制台共用同一问答链路。

🧠

模型可替换

OpenAI 兼容（DeepSeek 等）、Ollama 本地模型、内置 mock；Provider/模型可管理、可测试。

🛡️

本地可控

SQLite + 静态前端，单机即可跑；管理令牌、CSP、SSRF 防护、上传大小限制默认开启。

04三个关键亮点

如果只记住三件事：回答可核对、内容可运营、方案可落地。

1

可核对：不是“模型说”，而是“文件这么说”

回答里的每个 [n] 都能展开到：来自哪个词条、哪份源文件、哪个章节、哪段原文。学生可以点“下载原文件/查看原文”自行核对；老师也能一眼看出回答依据。

适合奖助、学籍、毕业、档案等“说错代价高”的场景。

2

可运营：辅导员在手机上就能维护知识

不需要懂技术：转发链接、粘贴微信文章、上传 Word/PDF，几分钟后变成可问答的词条；生成结果不理想可以编辑、重建、删除。没有 API Key 时也能用预编译快照离线演示。

把“知识库维护”从 IT 项目变成辅导员的日常动作。

3

可落地：单机、低成本、可离线

FastAPI + SQLite + 纯静态前端，无 Node 构建、无向量数据库、无额外中间件；一台电脑就能跑。模型可选 DeepSeek 等 OpenAI 兼容接口，也可用 Ollama 本地模型，或完全离线只读快照。

适合学院自建、内网试点、评审演示，再逐步扩展到公网。

05典型场景

角色他们用它做什么得到什么
学生问奖助、请假、宿舍、心理、就业、档案；看引用核对原文更快找到“文件里怎么说”，不再到处问人
辅导员转发通知/公众号文章、上传制度文件、校对词条减少重复答疑；知识沉淀成可复用资产

学生侧：一次提问的完整体验

  1. 用日常话提问

    “国奖需要什么材料？”“病假怎么请？”

  2. 拿到带引用的回答

    回答先给结论，再给步骤/材料，句末标注 [1]。

  3. 展开引用核对

    看词条、源文件、章节和原文摘录；可下载/打开原文。

  4. 没收录时

    助手尝试查学院官网/公众号，标注“临时来源”；仍找不到会建议联系辅导员。

辅导员侧：一条资料的入库路径

  1. 转发链接 / 粘贴正文 / 上传文件

    手机端“快速收录”三步完成。

  2. 等待编译

    通常几秒到十几秒；状态变为“已就绪”。

  3. 检查词条

    看标题、正文、来源是否对得上；可编辑或重新编译。

  4. 学生即可问到

    回答自动带词条与源文件引用。

06部署形态与成本

形态适合要点
本机演示评审、培训、个人试用.\scripts\run.ps1；无 Key 自动导入预编译快照；零配置。
校园局域网学院/学工部内部使用.\scripts\run.ps1 -Lan；手机扫码；必须设置管理令牌。

1 台普通电脑即可运行，无需额外中间件
0向量库 / embedding / rerank 依赖
10+支持 md/txt/pdf/docx/doc/xlsx/csv/json/html
4Web、QQ 官方、微信公众号、控制台入口

模型成本可控：只在“编译资料”和“生成回答”时调用模型；没有模型时仍可浏览词条、使用降级回答。也可接 Ollama 本地模型，把数据留在校内。

07安全与合规

  • 默认本地部署，数据存放在学校自己的服务器/电脑；可接本地模型进一步减少外发。
  • 管理写操作由 NPU_ADMIN_TOKEN 保护；对外监听未设令牌时服务拒绝启动。
  • CSP、X-Frame-Options、CORS 白名单、上传大小限制默认开启；URL 收录有 SSRF 防护。
  • 机器人凭据脱敏展示；微信回调校验 token/签名；QQ 官方校验平台凭据。
  • 引用可回溯到源文件，敏感/过期内容可由辅导员删除或重建。
  • 上线前请完成学校数据合规评估；涉及心理危机/人身安全时，AI 只做求助引导，不替代人工。

08当前边界与下一步

诚实说明能力边界，避免“什么都能做”的预期；以下能力已列入路线图。

当前版本（v0.1.7）边界

  • 不做个人系统查询：成绩、课表、请假审批、奖助进度需对接教务/学工系统。
  • 不做语音/图片理解；学生提问以文字为主。
  • 回答为同步返回，暂不支持逐字流式输出。
  • 管理端目前是单一管理令牌，未做多账号/角色。
  • 微信公众号为明文模式；QQ/微信长回答受平台长度限制。

下一步（v0.2.0 服务闭环）

  • 回答反馈：👍/👎 + 原因，自动汇总“学生没答好的问题”。
  • 知识缺口工作台：辅导员一键补资料、关联词条、关闭缺口。
  • 转人工与危机升级：工单、值班通知、紧急求助卡片。
  • 账号/角色/审计：多辅导员分权、操作可追溯。
  • 时效性与流式回答：来源日期/有效期、逐字输出、异步编译。

详细排期见项目 docs/ROADMAP.md 与 docs/PRD-v0.2.0.md。
